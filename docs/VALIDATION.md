## 测试环境的处理

Windows 原生测试进程在批量布局和截图时曾出现退出，当前采用 Chrome Widget 测试复现全部断言。

- tool/web_tests.py 连接专用测试 Chrome，将 CanvasKit 与测试字体请求映射到已安装 SDK 和本地字体文件，处理当前 Windows Flutter 测试服务器的路径兼容问题。
- Widget 测试使用已验证可解码的微型 PNG 替身，集中检查真实控件的布局与交互；字体加载使用项目 Manrope 字库。
- 96 张首屏、8 张长图使用真实照片、插画与字体。Android 集成测试也使用真实资源，完成图片解码后截图。

替身仅存在 test/test_assets.dart，不进入正式应用。截图用的固定购物车与订单仅在 tool/preview.dart，不进入正式入口。

## 页面范围与适配边界

开发覆盖 Pixso Light Mode 和 Dark Mode 内各 48 个编号 FRAME，组件标题不作为独立页面。见 [设计对应表](DESIGN_MAPPING.md)。

以原稿为参考进行 Flutter 原生界面重建，并对输入、滚动、导航及状态做了适配。列表使用有限示例商品，金额统一 USD；部分筛选、支付和成功页面重新排版；不宣称逐像素复刻。首屏截图外另附四个主要页面的深浅色长布局图，App 内也可继续滚动查看。

当前业务为本地演示，不含真实账户鉴权、短信/邮件、支付、订单配送、GPS、系统推送、社交登录或第三方分享。未验证 iOS。正式支付与鉴权服务需另行接入。

## 精简方式

- 48 个编号页面复用四个业务模块，深浅色共用一套控件。
- 统一按钮、输入框、卡片、底部导航与字体主题。
- 移除默认计数器应用及其测试，运行时仅保留 shared_preferences 一个直接第三方依赖。
- 图片压缩为 WebP，头像缩至实际显示所需尺寸。
- 使用 ChangeNotifier 与小型页面栈，避免为本地 UI 演示增加额外状态和路由依赖。
- 原稿图片、运行截图和测试固定数据分别存放，便于核对和继续开发。
